Glossary

Identity and access terms, in plain words.

42 terms. Each one says what the thing is, and where it matters links to a page that uses or tests it. These are my working definitions, written to be understood, not to replace a standard.

Last reviewed 14 November 2026. Lab data is made up; nothing here describes an employer or a client.

ABCDFHIJLMNOPRSTVZ

A

Access chain
My name for the seven steps every sign-in passes through: enroll and recover, prove, trust, decide, issue, act, watch and end. A weak step lets an attacker in even when the others are strong. See it used
Access review (recertification)
A regular check where an owner confirms that each person or account still needs the access it has. Access nobody confirms is removed. See it used
AI agent
Software that takes actions for a person or a team using a model, tools and credentials. For access purposes it is an identity: it needs an owner, a scope and an end date. See it used
API key
A long secret string that lets a program call a service. It usually has no expiry and no second factor, so who holds it and what it can reach matter a great deal. See it used
Authentication
Proving who you are. Passwords, passkeys and one-time codes are ways to authenticate.
Authorization
Deciding what an authenticated identity is allowed to do.

B

Blast radius
How much damage one stolen credential could do. It is the main input when ranking which credentials to fix first. See it used
Break-glass account
An emergency account used when normal access has failed. It should be separate, watched, tested, and rotated after every use. See it used

C

CIEM
Cloud infrastructure entitlement management. Tools and practice for finding and reducing what identities can do in cloud accounts. See it used
Conditional access
Rules that decide at sign-in whether to allow, block or ask for more proof, based on the user, device, location, app and risk. See it used
Continuous access evaluation
Checking a session again while it is running, so that a change such as a disabled account or a new network takes effect in minutes instead of when the token expires. See it used
Credential
Anything that proves an identity: a password, key, token, certificate or passkey.
Credential tiering
Sorting credentials into levels by what they can reach, so the most powerful ones get the strictest handling. See it used

D

Default deny
A rule set where a request that matches no rule is refused. Without it, the gaps between rules are open. See it used

F

Federation
One system trusting another to say who a user is. Single sign-on is built on it.

H

Human in the loop
A design where a person must approve a step before it runs. It only helps if the person sees exactly what will happen. See it used

I

IAM
Identity and access management. The whole field: who people and machines are, and what they may do.
Identity provider (IdP)
The system that signs users in and tells other apps who they are.
IGA
Identity governance and administration. Requests, approvals, reviews and the records that show access was granted for a reason. See it used

J

Just-enough access (JEA)
Granting only the specific rights a task needs, not a broad role. See it used
Just-in-time access (JIT)
Granting access when it is needed and removing it automatically afterwards, so nothing powerful sits idle. See it used

L

Least privilege
Give each identity the smallest set of rights that lets it do its job.

M

MCP
Model Context Protocol. A standard way for an AI application to call tools and reach data. Each tool call is an action someone should be able to approve and trace. See it used
MFA
Multi-factor authentication. Signing in with two or more different kinds of proof. Not all methods are equal: codes and push prompts can be relayed by a phishing page. See it used

N

Non-human identity (NHI)
Any identity that is not a person: service accounts, API keys, workloads, bots and agents. See it used

O

OAuth and OpenID Connect
OAuth lets an app act with limited rights without seeing the password. OpenID Connect adds sign-in on top of it.

P

PAM
Privileged access management. Controlling, recording and limiting the use of powerful accounts. See it used
Passkey
A sign-in credential tied to the real site and held on a device or security key. A fake site cannot reuse it, which is what phishing-resistant means. See it used
Phishing-resistant MFA
Methods such as passkeys and FIDO2 security keys, where the proof only works on the genuine site. See it used
PIM
Privileged identity management. Used mainly for time-limited activation of admin roles in a directory or cloud. See it used

R

Refresh token
A long-lived token used to get new short-lived access tokens without signing in again. If it survives a password reset, so does the attacker. See it used
Rotation
Replacing a secret with a new one. It limits how long a stolen secret works. It does not remove access from something that should not have it. See it used

S

SAML
An older, widely used standard for single sign-on between an identity provider and an app.
Secret
A credential used by software: a password, key or token stored in a vault, a pipeline or, too often, in code. See it used
Service account
An account used by software, not a person. It often has broad rights, no MFA and no clear owner. See it used
SSO
Single sign-on. Sign in once at the identity provider and reach many apps. See it used
Standing privilege
Powerful access that is always on, whether or not it is being used. See it used
Step-up authentication
Asking for stronger or fresh proof at the moment of a sensitive action. It only works if the server checks for it. See it used

T

Token binding
Tying a token to the device or client that received it, so a copy used elsewhere is refused. See it used

V

Vault
A system that stores secrets, controls who can read them, and records each use. See it used

Z

Zero standing privilege
A target state where no one holds powerful access by default. It is granted for a task and expires. See it used
Zero trust
Do not trust a request because of where it comes from. Decide each one on identity, device and context. See it used
