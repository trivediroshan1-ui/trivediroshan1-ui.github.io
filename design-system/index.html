Design system · v1

Colour says who acts.

One rule runs through this site and the MCP lab: every colour that carries meaning names an actor. Cyan is the policy gate. Violet is a person. Green is verified execution. Amber is audit and the unknown. Rose is refusal. Nothing else gets a glow.

04 Motion

Short, eased, and optional

Three durations: --hg-dur-fast 120ms, --hg-dur 220ms, --hg-dur-slow 480ms, all on --hg-ease. When the visitor asks for reduced motion, all three become 0ms. Nothing animates to fill space.

AA needs 4.5 : 1 for body text. Where an actor colour is used for a label, the label is also spelled out in words, so colour is never the only signal. Focus is a 2px outline with a 3px offset on every interactive element.

07 Rules

What keeps it consistent

  • Colour names an actor. If a colour does not mean policy, person, execution, audit or refusal, use ink.
  • One emphasis per block. A card gets one actor colour at most. Glow is reserved for the primary call to action.
  • Words before colour. Every status is written out. The colour supports it.
  • Mono is for labels. Section identifiers, ids, hashes and code. Never paragraphs.
  • Illustrative means labelled. A simulated flow says so beside it. Nothing static is dressed as a live feed.
  • Motion is optional. Everything works with it off.

Older pages still use their own variable names (--cyan, --accent, --safe). They share this palette and are being moved onto the tokens page by page. The tokens live in assets/tokens.css.
