Round 13 of the AI governance lab

Whether round nine's permission controls still hold when a document is found by meaning instead of words.

Last reviewed 14 November 2026

All rounds · Lab overview · Case explorer

Finding documents by meaning (round thirteen)

Round nine's assistant found documents by matching words. Real assistants usually find them by meaning, using an embedding model. The question for round thirteen: do the permission controls from round nine still hold when a document can be found without sharing a single word with the question? The answer model is still a stand-in that repeats what it is given, so no AI model that writes answers is tested. This round tests the wall around the search.

  2. The question and the documents become numbers The embedding model

    A small model turns the question and each document into numbers, so that similar meanings sit close together. It finds the HR salary document even when no word matches.

    • Embedding
    • Closest matches

    AI’s part: The embedding model only measures closeness. It does not know who may read what.

    Lab cases: S1

  3. Permissions are checked before the ranking The live directory

    The person's team is read from the live directory, and restricted documents are removed before the best matches are chosen. Done after, a restricted match can crowd out everything the person may read.

    AI’s part: None.

    Lab cases: S1S3S5

  4. Sources show only what the person may see The answer and its source list

    A title is not shown if the text is not. The source list follows the same permissions as the answer.

    AI’s part: None.

  5. Personal numbers were masked when the text went in Indexing

    An Aadhaar-format number was replaced with a mask when the note was indexed, so it stays hidden however the note is found.

    • Masked text

    AI’s part: None.

    Lab cases: S4

    Two documents that anyone may read can add up to a fact that is restricted. Permissions are checked one document at a time, so the lab cannot see it.

    • Joined facts

    AI’s part: None.

    Lab cases: S6

I wrote the expected result for 6 new cases (S1 to S6) and saved them before writing any code, on 25 Oct 2026 at 05:14 IST. I ran them with a real embedding model on my MacBook Air: sentence-transformers all-MiniLM-L6-v2, about 90 MB, run locally. The cases came out 6 of 6 as I guessed. Switching off one control at a time, in a copy of the code, was noticed by the matching case 5 of 5 times. S6 is a limit, so it has no control to switch off. In the sandbox, which cannot download a real model, a toy stand-in gave the same verdicts (6 of 6 and 5 of 5); the toy is not a real model and proves only that the code works.

My mistakes in this round

  • My first pay question contained the word “and”, which sits inside “band”, so keyword search would have found the HR document too. That would have spoiled the point of S1. I changed the question before any recorded run.
  • My first run on the Mac had all six cases “not run”. The install put NumPy 2 next to a torch built for NumPy 1, and every case failed with “Numpy is not available”. It also took 215 seconds because my code reloaded the model for every case. I fixed that, pinned NumPy below 2, and the next run took 43 seconds.
  • The control-off check from that broken run said “5 of 5 noticed”, but every case had failed with and without the control, and my checker counted an error as noticing. That number was meaningless. I fixed the checker so an error never counts and an invalid run is announced, and ran it again. The wrong file is kept next to the right one, on the Mac page.

What this does not show

  • One small embedding model, one question per case, and the best one to four matches. Another model or a different cut-off could rank differently, and S1 and S3 depend on the ranking.
  • S6 is a limit, not a fix: two documents anyone may read can add up to a secret, and the lab cannot see it.
  • With the real model, the top four for S6 included the document that carries a hidden instruction. This round did not test what happens next; round nine did, with keywords.
  • I wrote the guesses and the code, so “as expected” shows the controls do what I intended, not that I thought of every case. All six matched, which suggests my guesses were easy.
  • The mapping below is my own reading, not legal advice and not a certification.
