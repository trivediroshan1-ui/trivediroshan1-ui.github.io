Scope and out of scope

In scope

  • A made-up lender (Kaveri Finance) with made-up staff and customers
  • An AI use gateway, a guardrail filter, agent identity and audit evidence
  • Indian data formats: Aadhaar, PAN, UPI, IFSC, Indian phone numbers
  • One real assistant under one pasted policy, by hand

Out of scope

  • Any real person’s data, any real company’s systems
  • Product reviews of commercial tools
  • Legal advice. Any mapping to a law or standard is my reading
  • A claim that any of this is secure, or that I am the first to test it

The numbers in one place

  • 78 test cases over four rounds (41, 10, 13 and 14), plus 12 gateway scenarios, 16 controls and 6 modules.
  • Round one: the plain filter (v1) handled 20 of 53 variants; after fixes (v2), 42 of 53.
  • On the 200-sample set: catch rate 68 percent (v1), 90 percent (v2), 100 percent (v3). False alarms stayed at 5 percent.
  • On 10 items the filter had never seen: 4 of 10 for all three versions.
  • On 8 starter held-out cases written by the assistant that built the lab: v1 3 of 8, v2 2 of 8, v3 2 of 8.
  • Track P: 9 of 9 tests followed the policy, one assistant, one run, 24 October 2026.

The held-out cases

Eight starter items, all made-up data, written by the assistant that built the lab, so they are a first test and not an independent one. “Catch” means the filter should remove or mask something, “flag” means it should raise a warning, and “leave” means it should do nothing. They were committed to the repository before the filters were run on them.

Where everything is

  • The lab’s code, cases and results live in a git repository. run.py runs a round, heldout.py runs the held-out items, run_p.py shows and records the nine assistant tests.
  • Each round has a cases file with the guess written before the run. The results file stores a fingerprint of the cases file, so a changed guess shows.
  • The assistant test record is in results/track-p/. The held-out run is in results/held-out/.
  • The method is written up in docs/METHOD.md, the walkthrough in docs/TRACK-P.md, and the policy in docs/kaveri-ai-policy.md.

Glossary

AI use register
A list of every AI use the organisation has approved: who owns it, which model, what data, until when. If a use is not on the list, the gateway blocks it.
Gateway
One front door that every call to an AI model goes through. It checks the register, the model, the data and the tools, then writes the decision to a log.
Guardrail / filter
A check on what goes into a model or comes out of it. In this lab, the three filters (v1, v2, v3) look for personal data, secrets and hidden instructions.
Prompt injection
An instruction hidden inside content the AI reads (a web page, an email, a document) that tries to make it do something the user never asked for.
Held-out set
Test items written after the filter was finished, and committed before it was run on them. The honest test of whether a fix carries over.
Tuned set
The test items the filter was fixed against. A perfect score here proves little, because the fixes were made after seeing the misses.
Miss (false negative)
The filter should have caught something and did not.
False alarm (false positive)
The filter flagged something harmless, such as a laptop asset tag that looks like a PAN.
Masking
Replacing part of a value with symbols (for example, keeping only the last four digits of an Aadhaar) so the full value is not shown.
Aadhaar
India’s 12-digit personal ID number. In this lab the numbers are made up but pass the real checksum.
PAN
Permanent Account Number: the 10-character tax ID (five letters, four digits, one letter).
UPI, IFSC
UPI is India’s instant payment system, with addresses like name@bank. IFSC is the code that identifies a bank branch.
Hinglish
Hindi written in English letters, mixed with English. Many filters are built for English only.
Tamper-evident log
A log where each line includes a fingerprint of the line before it, so an edited line shows up. It cannot show lines cut off the end unless a copy of the final fingerprint is kept elsewhere.
Kill switch
A way to cut an agent’s access straight away, not after the next review.
Orphaned agent
An agent that still runs and still has access, but whose owner has left or who has not been used for a long time.
Short-lived credential
A token that expires in minutes or hours, so a stolen one stops working quickly.
Privilege on request
Access that is granted when needed and taken away after, instead of being held all the time.
Shadow AI
AI tools used without being registered or approved.
As expected / different
The lab’s result words. Each case has a written guess first. “As expected” means the guess matched; “different” means it did not.
Track P
The nine hand-run tests of a real assistant against the made-up policy.
