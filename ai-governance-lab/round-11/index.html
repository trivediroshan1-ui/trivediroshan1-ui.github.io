Round 11 of the AI governance lab

One agent handing work to another, what a compromised executor can sign, rotated keys and merged companies.

Last reviewed 14 November 2026

All rounds · Lab overview · Case explorer

Agents handing work to agents, keys and mergers (round eleven)

Round eleven is the part of my open list that was about agents and keys: what happens when one agent hands work to another, what a compromised executor or gateway can sign, what a replayed request does, what happens to a rotated key, what two merged companies do to staff IDs, and whether the PAN masking I skipped in round nine holds. It uses real public-key signatures (Ed25519), written in plain Python so the lab still needs nothing but Python.

The animation below follows one job from the person who starts it, through a chain of agents, to the log, and shows where each case sits. It is a design, tested here on small models I wrote, and it says who does each step.

  • The person who starts the job
  • Agents
  • Signing and keys
  • Directory and index
  • Logs and audit
  • HR and departures

  1. A person starts a job for an agent The person, with the agent's token

    The job is tied to the person who started it. The token the agent holds says who that is, and it is recorded at every step that follows.

    • Person
    • Token
    • Origin recorded

    AI’s part: Receives the job. It acts for this person and for nobody else.

    Lab cases: D3D4

  2. The agent hands part of the job to another agent The agent

    The next agent gets less, never more: a token cut down to what it is registered for and what the task needs. The chain has a depth limit, so it cannot grow without anyone noticing.

    • Narrower token
    • Depth limit

    AI’s part: Can ask another agent to help. Cannot give it more than it has.

    Lab cases: D1D2

  3. The hand-off cannot be replayed The identity layer

    A signed request or message carries a one-time number and a short window. A copy captured by a thief is refused the second time.

    • One-time number
    • Time window

    AI’s part: None. An AI model is not involved in this round.

    Lab cases: D5D10

  4. The gateway signs; the executor only checks The gateway and the executor

    The gateway signs with a private key. The executor holds only the public half, so a compromised executor cannot forge a decision. Each key has an identifier and a retirement time, so a rotated key stops working.

    • Private key
    • Public key
    • Key id and retirement

    AI’s part: None.

    Lab cases: D6D8

  5. High-risk actions need a second signature An approver, with a separate key

    Deleting a user is not decided by one signing point. A second signature from an approver whose key the gateway does not hold is required.

    • Second signature

    AI’s part: None.

    Lab cases: D7

  6. The log names the person and every hop The audit log

    One line shows the person who started the job and the agents it passed through, so the first question after an incident has an answer.

    • Person
    • Chain of agents

    AI’s part: None.

    Lab cases: D3

  7. The person leaves, and everything handed on stops HR and the identity provider

    Each handed-on token checks the one it came from, back to the start. Cutting the person cuts the whole chain.

    • Departure
    • Cascade

    AI’s part: None.

    Lab cases: D4

  8. Companies merge, and IDs get a prefix The directory

    Two staff both called S001 do not become one person. Every ID carries its company.

    • Company prefix

    AI’s part: None.

    Lab cases: D9

  9. Documents are masked after normalising The document index

    A PAN written in lower case or with a space is masked like one written in capitals. Round nine tested Aadhaar only.

    • Normalised text
    • Masked numbers

    AI’s part: None.

    Lab cases: D11

I wrote the expected result for 12 new cases (D1 to D12) and saved them before writing any code, on 25 Oct 2026 at 04:10 IST. The first run gave 11 of 12 as I guessed. The one that differed, D11, was a fault in my own test: it looked for one number written three different ways, so a hit in one document counted for all three. I fixed the test, not the guess, and all 12 then came out as guessed. I also reworked D12 after the first run, because the real limit is data handed from one agent to another, not permissions. Both result files are kept. I then switched off 11 controls one at a time in a copy of the code, and the matching case noticed 11 of 11. D12 has no such check, because it is a limit.

The SHA-256 of the guesses file is 4fd307467dbe1a9975fd984edcb3bb69f2cb4cc8b43c4e428f6f32961ff350ad. You can download the file and check it.

What this does not show

  • Everything is a small model I wrote. There is no real identity provider, no real tenant and no AI model.
  • The Ed25519 signing is my own plain-Python version of the standard algorithm. I checked it against the standard's test vector and against a well-known library on 20 random keys and messages. It is slow and not safe for real keys; it is only for these tests.
  • D12 is a limit, not a fix: two agents that are each allowed can still move data together.
  • D11 uses a small search index, not the full document assistant from round nine, and one made-up PAN pattern.
  • I wrote the guesses and the code, so “as expected” shows the rules do what I intended, not that I thought of every case.
  • This round ran in a Linux sandbox with Python 3.11 and on my MacBook Air (Python 3.9.6) with the same verdicts: 12 of 12 as guessed and 11 of 11 control-off checks noticed. Both sets of files are on the run page.
