Step 4: Store and issue

Secrets in an approved place, short-lived, never in code.

A secret belongs in an approved store, short-lived where you can make it so, and never in code, tickets or chat. This step covers scanning, per-job credentials, vault backups and the paths a secret takes once it leaves the vault.

What the cases in this step showed

  • The scan blocked 6 of 8 planted secrets. The 2 it missed matched no pattern.
  • A token copied from a CI runner was replayed twice until it was bound and revocable.
  • A vault backup on a weaker share let 5 non-backup reads through.

A question to ask

Where can a secret be read today that is not the approved store?

10 cases follow. Guesses that were wrong: S-R17-05, N-R14-25, C-R16-C01, N-R18-01, P-R15-06. Controls nothing noticed: N-R14-25, C-R16-C01, C-R16-C02, N-R18-01, P-R15-06.

Step 4: Store and issue · Run 1 · Front door and trust · OWASP NHI6 · Guess matched

A pipeline holds a cloud key that is 400 days old. A job from another project on the same runner reads the variable.

Diagram for case N-R14-03: see it on the lab page.

GUESSMatched in both runs (control off, control on).

TAKE-AWAYA long-lived key shared by a pipeline can be read by any job on it. One credential per job makes the log name the job that used it.

N-R14-25 Credential stolen from a CI runner, replayed

Step 4: Store and issue · Run 1 · Gap cases from 2026 incidents · OWASP NHI4, NHI6, NHI7 · Guess wrong · Control masked · Limit recorded

A job runs for 5 minutes with a deploy token. A malicious step copies the token at minute 1. The attacker replays it at minute 3 from another network, and again at minute 8 after the job ended.

Diagram for case N-R14-25: see it on the lab page.

GUESSWrong. I guessed a short token lifetime would change whether a replay worked. It changed nothing. Binding the token and revoking it already refused both replays.
MEASUREDWithout: replay min3 yes, replay min8 yes. With: replay min3 no, replay min8 no.
EXTRA SCENARIO10-minute lifetime only. Result matched my guess.
TAKE-AWAYA token copied from a CI runner was replayed twice. Binding the token and revoking it refused both. I guessed a short lifetime would matter and it did not, because the binding had already blocked the replay.

C-R16-C01 The forgotten service account

Step 4: Store and issue · Run 2 · Chain tests · Guess wrong · Control masked

Chain of links: no owner, password never rotated, copied to a ticket, ticket export shared, sign-in from a new network.

Diagram for case C-R16-C01: see it on the lab page.

GUESSWrong. I guessed the secret scan on tickets would be the most useful single control. The owner rule was. It stops the chain at the first link.
MEASUREDWithout controls: the attacker reaches the last link. With all controls: stopped at link 1. Each control alone: Owner required stops it at link 1; Secret scan on tickets stops it at link 2; Rotation stops it at link 4. Best single control: Owner required.
EXTRA SCENARIOAccount already exists (legacy), owner rule cannot apply. Result matched my guess.
TAKE-AWAYFive links from no owner to a sign-in from a new network. The owner rule stops it at the first link. I guessed the ticket scan would matter most, and the owner rule did. For an account that already exists the owner rule cannot apply, and the ticket scan stops it at the second link.

C-R16-C02 The token in the repository

Step 4: Store and issue · Run 2 · Chain tests · OWASP NHI2, NHI6 · Guess matched · Control masked

Chain of links: token committed, repo cloned, scanner finds it, attacker calls the cloud API.

Diagram for case C-R16-C02: see it on the lab page.

GUESSMatched in both runs (control off, control on).
MEASUREDWithout controls: the attacker reaches the last link. With all controls: stopped at link 1. Each control alone: Block secrets at commit stops it at link 1; Short-lived tokens stops it at link 4; Revoke on find does not stop it. Best single control: Block secrets at commit.
EXTRA SCENARIOThe finder is faster than the token lifetime (12 hours). Result matched my guess.
TAKE-AWAYThe commit block stops a token at link 1. A one-day token alone also stops the chain when the finder takes 7 days. If the finder is quicker than the token lifetime (12 hours), the short token alone no longer helps.

N-R18-01 A copied key from another network

Step 4: Store and issue · Run 3 · Front door and trust · OWASP NHI4 · Guess wrong · Control masked · Limit recorded

An internal payments API accepts a static key from the billing service. In one hour there are 12 calls: 6 genuine from the billing workload, 3 replays of a copied key from an unknown network, and 3 calls with the old key after it was rotated 2 days ago.

Diagram for case N-R18-01: see it on the lab page.

GUESSWrong. I guessed 3 alerts with all controls on. The result was 1 alert. The model raises one alert per new network, and all 3 replays came from the same network. Replays from 3 networks gave 3.
MEASUREDWithout: accepted 12, refused 0, alerts 0, replays accepted 3, old key refused 0, can tell apart no. With: accepted 6, refused 6, alerts 1, replays accepted 0, old key refused 3, can tell apart yes.
EXTRA SCENARIOBinding off. Result matched my guess.
EXTRA SCENARIORevocation off. Result matched my guess.
EXTRA SCENARIOAlert off. Result matched my guess.
EXTRA SCENARIOReplays from three different networks, all controls on. Result matched my guess.
TAKE-AWAYA key copied to another network was replayed 3 times among 12 calls. Without a binding, the log showed "billing key" 12 times and nobody could tell the 6 genuine calls from the bad ones. With the key bound to the workload, the 6 bad ones were refused. I guessed 3 alerts and got 1, because the model raises one alert per new network. A call from inside the real workload still passes.

N-R14-02 Secrets in code, config, chat and tickets

Step 4: Store and issue · Run 4 · Discover · OWASP NHI2 · Guess matched · Limit recorded

20 fake secrets are planted. 8 in repository files (one split over two lines, one in base64), 4 in config files, 4 in a chat export, 4 in tickets (one only in an attached screenshot).

Diagram for case N-R14-02: see it on the lab page.

GUESSMatched in both runs (control off, control on).
MEASUREDWithout: found 0, still live 20, missed in scanned places 0, missed kinds none. With: found 17, still live 3, missed in scanned places 3, missed kinds base64, image, split.
EXTRA SCENARIORepo and config scan off. Result matched my guess.
EXTRA SCENARIOChat scan off. Result matched my guess.
EXTRA SCENARIOTicket scan off. Result matched my guess.
TAKE-AWAYThree scans, each pointed at the places it covers, found 17 of 20 planted secrets. The other 3 sat inside scanned places: one split over two lines, one in base64 and one in a screenshot. Switching off any one scan left its places unprotected. No scan reads images, so the screenshot secret stays missed.

P-R15-06 The person never sees the password

Step 4: Store and issue · Run 4 · Privileged access · OWASP NHI2 · Guess wrong · Control masked · Limit recorded

10 privileged sessions go through a broker. 2 users try to reveal the password in the console. 3 users later try to log in directly with a password they remember.

Diagram for case P-R15-06: see it on the lab page.

GUESSWrong. I guessed the credential injection would matter when switched off alone, and that rotation after each session was safe to drop. The reveal policy still stopped both reveals, so the injection went unnoticed. Without rotation all 3 remembered passwords still worked.
MEASUREDWithout: sessions ok 10, reveals 2, direct logins ok 3, direct logins refused 0. With: sessions ok 10, reveals 0, direct logins ok 0, direct logins refused 3.
EXTRA SCENARIOInjection off. Result differs from my guess: {'reveals': [2, 0]}.
EXTRA SCENARIORotation off. Result differs from my guess: {'direct_logins_refused': [3, 0]}.
TAKE-AWAYThe credential injection and the disabled reveal button each stopped both reveals alone, so each hid the other. Rotation after every session is what refused the 3 passwords the users remembered. I got both parts of this wrong. A keylogger on the user machine is outside all three controls.
