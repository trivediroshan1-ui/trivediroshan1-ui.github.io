Before you start

Who it is for, how to read it, and how to read a case diagram.

Who this is for

  • Platform owners and IAM or PAM engineers who run service accounts, vaults, pipelines and AI integrations.
  • Security architects who need to choose controls and explain the choice.
  • Auditors and risk owners who want to see what was tested and what was not.
  • Anyone who has been told that machine identities outnumber people and wants to know what to do about it.

How to read a case diagram

Each of the 67 cases has the same kind of picture, so once you have read one you can read them all. The numbers on the boxes match the numbers below. This example is case N-R14-15, which is about rotating a password in the wrong order.

Diagram for case N-R14-15: see it on the lab page.

  1. Event. What happens in the case, in one line.
  2. Control. The rule or check being tested. Some cases test more than one.
  3. Without the control. What the model did when the control was off. The dashed red line shows the path.
  4. With the control. What it did when the control was on.
  5. Switch each control off alone. If switching one control off changes the result, a check noticed it (green). If nothing changes, the control was masked by another or did not matter in this case (amber).
  6. What it cannot see. The limit I recorded. Grey and empty means I found none, which is not the same as there being none.

Chain tests look a little different. The top row shows the attacker's links. A flag under a link shows where a control acts: it stops the attacker there, only reports, arrives too late, or has no effect.

A note on the data

Every account, bank and number in this book is made up. The bank is called Kaveri Finance and does not exist. Nothing relates to any employer, client or real company. The models are small and run in memory.

What changed since edition 1

The first edition had 27 cases and 21 pages. This one has 67 cases, a workflow diagram for each, the framework, a dated market chapter, a method chapter that lists my mistakes, an audit appendix, a roadmap and a glossary.
