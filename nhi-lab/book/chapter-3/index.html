Machine identities, tested in public · Chapter 3

What I did

The procedure, the dates and the mistakes. Enough detail to repeat it.

The approach in one paragraph

Pick a failure and a control that should stop it. Write what I expect with the control off and on. Hash the guess file and commit it. Only then write a small in-memory model of the control, run it twice, and compare. Switch each control off alone to see whether anything notices. Write down what the control cannot see. Run it again on a second machine and compare the output.

The procedure in one picture

  1. Write the guess Two lines per case: without the control, with it.
  2. Hash the file SHA-256 of the whole guess file.
  3. Commit it On its own, before any code exists.
  4. Write the model A small in-memory copy of the control.
  5. Run, control off Compare with the guess.
  6. Run, control on Compare with the guess.
  7. Switch each control off alone Did anything notice?
  8. Record misses and limits Wrong guesses stay on the page.
  9. Run again on the Mac Output must match the sandbox.

The steps, with what you should see

#StepExpected result
1Write the guess. Numbers, not "better". Two lines per case.A guess file. Nothing has been run.

7Switch each control off alone. If the result does not change, no check noticed that control."Noticed" or "masked" for each control.

9Run again on a second machine and compare the output.Identical output. If not, stop and find out why.

Careful with the commit

Commit only the guess file before the code. On my Mac I once ran git add with no paths, and I ran a hash command with no file name, which waits for input. Both were harmless and both cost time.

What the words mean

TermMeaning in this book
MatchThe result equals what the guess said, in both runs.
Wrong guessA number or a ranking in the guess did not equal the result. The book keeps both.
NoticedSwitching that one control off changed a result.
MaskedSwitching it off changed nothing, because another control covered it or the control did not matter in that case.
LimitWhat the control cannot see. Every case should have one.
Chain testA series of links an attacker needs. The test records which link each control stops.

What went wrong

These are the mistakes, in the order they matter. The first ten are wrong guesses. The last two are mistakes in my own test harness.

What went wrongCaseWhat I did
I guessed the scan would miss 1 secret. It missed 2.S-R17-05Recorded. The 2 misses were a secret split over two lines and one in base64.
I guessed a short token lifetime would change the replay result.N-R14-25It did not. Binding and revoking already refused both replays. Recorded.
My own arithmetic was wrong.N-R14-07Nine identities with two or three names each cannot make 51 entries. The count is 43. A rule that stripped trailing digits also merged two real accounts. Recorded.

I guessed 3 alerts for 3 replays of a copied key.N-R18-01The model gave 1, because it raises one alert per new network and all 3 replays came from one network. Recorded.

I guessed 4 alerts for 5 creation attempts.S-R17-09The model alerts on every attempt, refused or not. I never wrote down which I meant. Recorded.

Checking it again on 2 November 2026

After the second run I re-ran everything in the build sandbox. The verify script printed 5 of 5 guess files match their recorded hash. Running run.py and run2.py gave results identical to the committed ones, except for the time stamp. The Mac output of the second run had already matched the sandbox. On 10 November 2026 the verify script covers 6 guess files, and the round 19 results file has the same SHA-256 on the Mac and in the sandbox.

What this method cannot tell you

  • I wrote the guesses and the code. A match shows my model agrees with my reasoning. It does not show that a real product behaves that way.
  • A hash proves the file did not change after I committed it. It does not prove when I wrote it, beyond the commit time.
  • Chain tests are rule models. Each link is stopped by the controls I decided stop it, so the results follow from my rules.
  • Three chain tests have an extra scenario I wrote after the fact to probe a limit. Each is marked as an extra.
