Lab

The virtual lab

Pick any case. Read the guess I locked before running anything. Switch the controls. See the output my script produced. Then run the same script on your own computer.

  • 114 cases replayed
  • Python 3, no packages
  • Made-up data only

What this is, and is not

This page replays saved output. Nothing is simulated in your browser. The numbers below are the ones my scripts wrote to their result files on 14 November 2026.

If you want to see a script run, the second half of this page has the steps for your own computer. It takes a few minutes.

Replay a case

Run it yourself

Run 5 is the newest. It uses only Python 3’s standard library. The other runs work the same way.

  1. Check Python. python3 --version should print a version that starts with 3.
  2. Make a folder and download two files. 
    mkdir ca-lab && cd ca-lab
curl -O https://roshantrivedi.co.in/ca-mfa-lab/evidence/run5.py
curl -O https://roshantrivedi.co.in/ca-mfa-lab/evidence/guesses/guesses-run5.md
  3. Check that the guesses are the locked ones. 
    shasum -a 256 guesses-run5.md
    It should print bc344bbd00d01d169c0dbde94d83fc628ec973dcbbb067d1c2cad3f74a65e63a. The script checks this itself and refuses to run if the file differs.
  4. Run it. 
    python3 -I run5.py guesses-run5.md
    You should see 12 lines that end in OK, two summary lines, and five lines that start with SENS. It writes results-run5.json next to the script.
  5. Break an assumption. Open run5.py and find PARAMS near the top. Change p_no_read from 0.30 to 0.02 and run again. W10 and W11 change. Because the script checks the guess file’s hash, the guesses cannot be quietly changed to match.
  6. Try the older runs. They live in the same evidence folder. From inside that folder: python3 run1.py, python3 run2.py guesses/guesses-run2.md, python3 run3.py guesses/guesses-run3.md.
  7. Write your own guess first. Pick a case, write what you expect for each switch, save it, hash it, and only then look at the output. That order is the whole method. How the method works.

What changes when one assumption changes (Run 5)

I changed one assumption at a time and re-ran all 12 cases. These are the only changes that flip any result.

Assumption changedCases that change
p_no_read 0.02 (people almost always read)W10, W11
p_no_read 0.60No case changes
session_hours 25 (cloud session outlasts the wait)W02
attacker_delay_min 10 (replay after the short token ends)W09
b_covers_all_credentials True (step-up check applies to keys and service tokens)W08

The 30 percent, the 2 minutes and the 1 hour are numbers I chose. They are written at the top of the script so you can change them.

Tests you can only do by hand

Three cases need a real tenant, a hardware key or a person: sign-in logs and a report-only policy, a lost hardware key, and a help desk call. They are on the Run 4 page with setup and safety notes. If you run one, tell me what you saw.

Limits

  • The replay shows my models. Your product may behave differently.
  • Run 1 stored three columns (no control, control on, control off alone). Runs 2, 3 and 5 store five (none, all, off A, off B, off C).
  • The assumption test was only run for Run 5.
