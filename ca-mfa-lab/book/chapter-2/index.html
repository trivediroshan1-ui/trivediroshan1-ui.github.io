Who signs in? · What is in, what is out, and how each case was run

Scope and method

In scope

  • MFA and 2FA methods: SMS, TOTP, push, number matching, passkeys and security keys.
  • Single sign-on: SAML, OpenID Connect and OAuth flows, federation and signing keys.
  • Conditional access policy logic, context signals, exceptions and emergency accounts.
  • Account recovery and help desk resets.
  • Tokens: scope, lifetime, binding, refresh and revocation.
  • CI/CD cloud trust, API integrations, MCP clients and servers, and AI agents acting for people.

Out of scope

  • How any named product behaves. I did not test vendors.
  • Real tenants, real people and real data. Six hand tests are left for readers.
  • Performance, cost and user experience.

How a case was run

  1. Pick a failure from the catalogue and the controls that should stop it. Write down the bad outcome first, so I know what I am counting.
  2. Write the expected result with no controls, with all controls on, and with each control switched off on its own.
  3. Save the guesses, hash the file with SHA-256 and commit it. Merge it before any model code exists.
  4. Write the model, run it, and compare the output with the parsed guess file. The script refuses to run if the guess file's hash differs.
  5. Record every miss. Fix my own coding mistakes in the open and keep the first-pass files.
  6. For Runs 5 and 6, change one assumption at a time and record which results flip.

Why the perfect runs prove little

I wrote each model after its guesses. A perfect score shows that my model and my reasoning agree. Nothing outside me tested the guesses. Run 2 was the only run that caught me out, and it taught me the most.
