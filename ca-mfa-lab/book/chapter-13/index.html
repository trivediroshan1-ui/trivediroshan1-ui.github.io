Who signs in? · Dated events behind the cases

What companies are suffering

The cases come from public reports. Each event below has a date, the lab cases it relates to, the kind of source, and how far I trust it. Companies appear because the sources name them. A name here says nothing about that company's controls today.

DateWhat was reportedCasesSource and trust
6 Nov 2026SonicWall SSLVPN: a user with valid credentials for another login method can bypass SAML, including SAML-enforced MFA (CVE-2026-19868). Applies only when SAML is on for VPN logins. SonicWall’s advisory says it investigated a report indicating potential exploitation, and CISA added the flaw to its Known Exploited Vulnerabilities list the same day. Fixed in 7.3.4-7013 (Gen7) and 8.2.3-8015 (Gen8). Revision 1.1 on 9 November added a workaround: if SAML is in use and you cannot upgrade, disable or delete the active LDAP, RADIUS and TACACS+ servers.W05SonicWall advisory SNWLID-2026-0014, revision 1.1; CISA KEV entry. Confirmed against SonicWall’s own page on 14 November. My earlier note said there was no workaround; that was true until revision 1.1. The page’s revision table dates version 1.0 as 5 November, its header says 6 November.
28 Sep 2026The official MCP Python SDK did not check the issuer on a fallback discovery path. A malicious MCP server could make an SDK-based client send its client secret, authorization code and PKCE verifier to an endpoint the server chose (GHSA-qx49-fqc8-xw99, CVSS 7.5). Fixed in 1.30.0 and 2.2.0. No attacks have been reported.W11Project security advisory, read through a Cloud Security Alliance note (30 Sep 2026) and The Hacker News. Confirmed, with a qualifier: I did not open the GitHub advisory. MCP was created by Anthropic, whose Claude model helped me draft this lab.
24 Aug 2026Okta made Agent SSO generally available. It registers AI agents as identities, issues short-lived tokens in place of stored credentials, and moves agent authorization to the identity provider using Cross App Access. The release does not say how revocation works.G01 E04Vendor press release. Confirmed as Okta’s own announcement, read through a page summary on 14 November. Product claims are the vendor’s.
15 Jul 2026GitHub moves new repositories, and repositories that opt in, to an immutable subject claim in OIDC tokens. Cloud trust policies must include the numeric owner and repository IDs.W01Vendor documentation. Confirmed against GitHub’s live docs on 14 November, through a page summary. Repositories created after the date use the new format by default, older ones can opt in, and renames and transfers after it also move. Not available on GitHub Enterprise Server.
Reported 17 Mar 2026Researchers at NetSPI showed that certain nested app authentication flows could return Microsoft Graph tokens without Conditional Access being applied. They told Microsoft on 17 March, Microsoft rated it medium and deployed a fix, and a retest returned Conditional Access blocking errors. Other researchers presented further nested app paths at TROOPERS 2026.Y06Researcher write-up. Partly confirmed: I read excerpts of the NetSPI post and a news write-up, not Microsoft’s own statement. The fix covers the flows NetSPI named, not every nested app path.
27 Jan 2026Microsoft revised the Exchange Online timeline for ending Basic authentication on SMTP AUTH (the path older printers and scanners use). It stays unchanged until December 2026, is then disabled by default for existing tenants and unavailable by default for new ones, and a final removal date is due in the second half of 2027. The earlier March to April 2026 dates were put on hold.Z20Vendor announcement (Exchange Team blog, updated 29 Jan). Confirmed, through a page summary. Dates have moved before, so check Microsoft’s page before you act.
22 Jan 2026Okta Threat Intelligence described phishing kits built for phone callers. The caller steers what the user sees in step with their script, which defeats any MFA that is not phishing-resistant. Okta says number matching is not phishing-resistant by definition.M01 M03 M04 Z01 W12Vendor research by the identity provider; primary for what Okta observed. Confirmed as Okta’s own finding. The full advisory is for Okta customers only.
1 Oct 2025Microsoft began enforcing MFA for Azure resource management at the Azure Resource Manager layer (Phase 2), for CLI, PowerShell, SDKs and REST calls. Tenants could postpone to 1 July 2026. Workload identities such as managed identities and service principals are not covered.Y01 Y02 W08Vendor documentation and announcement. Confirmed. Enforcement is gradual by tenant, so your tenant may differ.
8 to 20 Aug 2025Stolen OAuth and refresh tokens from the Salesloft Drift integration were used to read data from many customers’ Salesforce instances between 8 and 18 August. Salesloft and Salesforce revoked all Drift tokens on 20 August. Google later confirmed Drift Email tokens were also compromised.W06 W07Google Threat Intelligence Group report, 26 Aug 2025. Confirmed by the investigating team. My reading: tokens like these are used without a fresh sign-in, so MFA had nothing to check.
9 Jul 2025mcp-remote, a tool that connects AI clients to remote MCP servers, ran operating system commands from a crafted authorization endpoint sent by a malicious server (CVE-2025-6514, CVSS 9.6). Fixed in 0.1.16.W11Researcher advisory and CVE record. Confirmed. A related lesson to W11, not the same flaw: the client trusted values the server supplied. W11 matches the Python SDK advisory above.
14 to 18 Mar 2025The GitHub Action tj-actions/changed-files was compromised and leaked CI/CD secrets through workflow logs (CVE-2025-30066). CISA added it to its Known Exploited Vulnerabilities list.W02 W03Government alert. Confirmed.
16 Nov 2023, updated 29 Jul 2025CISA and the FBI described a group that phones IT help desks, poses as an employee and has the password reset and MFA moved to a device they control.W12 E03Government advisory AA23-320A. Confirmed.
