Who signs in? · Terms in plain words

Glossary

TermMeaning
AALAuthenticator assurance level in NIST SP 800-63B. AAL3 needs a hardware-bound key that cannot be copied.
Access tokenA short-lived credential an app presents to an API. Whoever holds it can usually use it.
AiTMAdversary in the middle. A phishing proxy that relays the real sign-in and steals the session cookie after MFA.
AssertionA signed statement from an identity provider that a user signed in, for example a SAML assertion.
AudienceThe app or API a token or assertion is meant for. An app that does not check it may accept a token meant for another.
Authorization serverThe service that issues OAuth tokens.
Break-glass accountAn emergency account kept outside normal rules so admins are not locked out.
Conditional accessRules that decide whether a sign-in is allowed, blocked or needs more proof, based on user, app, device and context.
Consent phishingTricking a user into granting a malicious app access, with no password stolen.
Continuous access evaluationRe-checking a session after sign-in when something changes, such as a revoked user or a new network.
Cross App AccessAn approach where an AI agent gets access to a second app through the enterprise identity provider.
Device code flowAn OAuth flow for devices without a keyboard. Attackers use it to get a victim to approve their code.
DPoPDemonstrating Proof of Possession (RFC 9449). Binds a token to a key so a copied token fails from another machine.
Exclusion groupA group left out of a policy. It tends to grow.
FederationTrusting another identity provider's sign-ins and claims.
FIDO2 and WebAuthnStandards behind passkeys and security keys. The key signs only for the real site's origin.
Golden SAMLForging SAML assertions with a stolen identity provider signing key.
Help desk resetStaff resetting a password or MFA for a caller. A common way in for social engineers.
Identity provider (IdP)The service that signs users in and vouches for them to apps.
IssuerThe identity provider or authorization server named in a token or metadata.
Legacy authenticationOld sign-in protocols, such as SMTP AUTH with a password, that cannot do MFA.
MCPModel Context Protocol. A way for AI applications to connect to tools and data. Its authorization uses OAuth.
MFA, 2FASigning in with more than one kind of proof. 2FA means exactly two.
NonceA one-time value that ties a response to the request that asked for it.
Number matchingA push prompt where the user types a number shown on the sign-in screen, which stops blind approval.
OIDCOpenID Connect. A sign-in layer on top of OAuth that issues ID tokens.
OAuthA framework for granting apps limited access to resources with tokens.
On behalf ofAn agent or service acting for a person. The token should carry who that person is.
PasskeyA FIDO credential that replaces a password. It can be synced across devices or bound to one.
Phishing-resistant MFAMFA a look-alike site cannot relay, such as passkeys and security keys.
PKCEProof Key for Code Exchange. Stops an intercepted authorization code from being used by someone else.
Privileged accessAccess that can change security settings, data or other people's access.
Push fatigueSending prompts until a tired user approves one.
Redirect URIWhere an authorization server sends the code or token. It must match exactly.
Refresh tokenA longer-lived credential that gets new access tokens without signing in again.
Report-only modeRunning a policy that logs what it would do without enforcing it.
ROPCResource owner password credentials. Sending a password straight to the token endpoint, which cannot do MFA.
SAMLSecurity Assertion Markup Language. An older SSO standard based on signed XML assertions.
Service accountAn account used by software, not a person.
SessionThe period after sign-in when a cookie or token keeps a user signed in.
SIM swapMoving a phone number to an attacker's SIM to receive SMS codes.
SSOSingle sign-on. One sign-in at the identity provider gives access to many apps.
Step-upAsking for fresh, stronger proof before a sensitive action.
Sub-agentAn agent started by another agent to do part of a task.
Token bindingTying a token to a device or key so it cannot be used elsewhere.
Token exchangeSwapping one token for another with narrower scope, for example when delegating (RFC 8693).
TOTPTime-based one-time password from an authenticator app.
Trusted locationA network range a policy treats as safer, often to skip MFA.
Workload identityAn identity for software, such as a pipeline or a cloud function, that uses short-lived federated tokens.
