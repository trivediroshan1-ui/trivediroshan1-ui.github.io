Sources and recent events

What happened to real companies and products, which lab case each event relates to, and how far I trust each source. Checked on 14 November 2026.

  • Each one labelled

How to use this page

The lab runs on made-up data. These events are why the cases exist. Each row says what was reported, who reported it, and how well I could confirm it.

I name an event only when I read a primary or near-primary source for it: a vendor advisory, a government alert, a standard, or the investigating team’s own report. News coverage is labelled as news. Where I read a report quoting a vendor page but not the page itself, I say so. Company names appear because the sources name them, and a name here is not a finding about that company’s controls.

6 Nov 2026SonicWall SSLVPN: a user with valid credentials for another login method can bypass SAML, including SAML-enforced MFA (CVE-2026-19868). Applies only when SAML is on for VPN logins. SonicWall’s advisory says it investigated a report indicating potential exploitation, and CISA added the flaw to its Known Exploited Vulnerabilities list the same day. Fixed in 7.3.4-7013 (Gen7) and 8.2.3-8015 (Gen8). Revision 1.1 on 9 November added a workaround: if SAML is in use and you cannot upgrade, disable or delete the active LDAP, RADIUS and TACACS+ servers.W05SonicWall advisory SNWLID-2026-0014, revision 1.1; CISA KEV entry
SonicWall advisory, CISA KEV, SecurityWeek		Confirmed against SonicWall’s own page on 14 November. My earlier note said there was no workaround; that was true until revision 1.1. The page’s revision table dates version 1.0 as 5 November, its header says 6 November.
28 Sep 2026The official MCP Python SDK did not check the issuer on a fallback discovery path. A malicious MCP server could make an SDK-based client send its client secret, authorization code and PKCE verifier to an endpoint the server chose (GHSA-qx49-fqc8-xw99, CVSS 7.5). Fixed in 1.30.0 and 2.2.0. No attacks have been reported.W11Project security advisory, read through a Cloud Security Alliance note (30 Sep 2026) and The Hacker News
CSA note, The Hacker News		Confirmed, with a qualifier: I did not open the GitHub advisory. MCP was created by Anthropic, whose Claude model helped me draft this lab.
15 Jul 2026GitHub moves new repositories, and repositories that opt in, to an immutable subject claim in OIDC tokens. Cloud trust policies must include the numeric owner and repository IDs.W01Vendor documentation
GitHub Docs: OIDC reference		Confirmed against GitHub’s live docs on 14 November, through a page summary. Repositories created after the date use the new format by default, older ones can opt in, and renames and transfers after it also move. Not available on GitHub Enterprise Server.
Reported 17 Mar 2026Researchers at NetSPI showed that certain nested app authentication flows could return Microsoft Graph tokens without Conditional Access being applied. They told Microsoft on 17 March, Microsoft rated it medium and deployed a fix, and a retest returned Conditional Access blocking errors. Other researchers presented further nested app paths at TROOPERS 2026.Y06Researcher write-up
NetSPI blog		Partly confirmed: I read excerpts of the NetSPI post and a news write-up, not Microsoft’s own statement. The fix covers the flows NetSPI named, not every nested app path.
27 Jan 2026Microsoft revised the Exchange Online timeline for ending Basic authentication on SMTP AUTH (the path older printers and scanners use). It stays unchanged until December 2026, is then disabled by default for existing tenants and unavailable by default for new ones, and a final removal date is due in the second half of 2027. The earlier March to April 2026 dates were put on hold.Z20Vendor announcement (Exchange Team blog, updated 29 Jan)
Exchange Team blog		Confirmed, through a page summary. Dates have moved before, so check Microsoft’s page before you act.
22 Jan 2026Okta Threat Intelligence described phishing kits built for phone callers. The caller steers what the user sees in step with their script, which defeats any MFA that is not phishing-resistant. Okta says number matching is not phishing-resistant by definition.M01 M03 M04 Z01 W12Vendor research by the identity provider; primary for what Okta observed
Okta blog		Confirmed as Okta’s own finding. The full advisory is for Okta customers only.
1 Oct 2025Microsoft began enforcing MFA for Azure resource management at the Azure Resource Manager layer (Phase 2), for CLI, PowerShell, SDKs and REST calls. Tenants could postpone to 1 July 2026. Workload identities such as managed identities and service principals are not covered.Y01 Y02 W08Vendor documentation and announcement
Microsoft Learn, Azure blog		Confirmed. Enforcement is gradual by tenant, so your tenant may differ.
8 to 20 Aug 2025Stolen OAuth and refresh tokens from the Salesloft Drift integration were used to read data from many customers’ Salesforce instances between 8 and 18 August. Google Cloud blog		Confirmed by the investigating team. My reading: tokens like these are used without a fresh sign-in, so MFA had nothing to check.

What I left out, and why

  • Claims that a hacking group stole data from named companies through Okta sign-ins. They rest on the group’s own statements or one blog, and the companies did not confirm them.
  • A report of one company’s breach through single sign-on followed by its CRM, from a single blog.
  • Several 2026 reports of CI/CD and MCP package compromises that I could find in one blog each. I will add them when I can read the maintainers’ own notice.
  • Anything about the internal workings of a product I have not read the vendor’s documentation for.

Limits

  • Dates and fixed versions change. Check the source before you act on any row.
  • I used search results and excerpts for several rows and opened few pages in full. The “how far I trust it” column says which.
  • This is not legal advice, and it is not a vulnerability scanner. If you run a SonicWall device with SAML on, read the vendor advisory and patch.
