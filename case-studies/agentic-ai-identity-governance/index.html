Agentic AI Identity Governance

AI agents request permissions, spawn sub-agents and chain actions across systems at runtime — a governance model built for static roles and long-lived credentials, applied to an identity that changes shape while it runs.

Credential Management Platform Owner & PAM Product Owner

The challenge

Agent frameworks let an AI acquire scopes, call APIs and launch sub-agents dynamically, so the identity a workflow ends up using is decided at runtime, not at provisioning. Most IAM stacks assign a role once and assume it holds; most access reviews assume a point-in-time snapshot still describes what an agent can do. Neither assumption survives an agent that can request a new capability mid-task.

The approach

  • Issued every agent a scoped, short-lived credential tied to a single task rather than a standing role, so a compromised or misbehaving agent carries only the blast radius of the task it was running.
  • Replaced point-in-time access review with continuous re-authorization: each new permission request or sub-agent spawn is evaluated against policy at the moment it happens, not caught at the next audit cycle.
  • Routed agent actions above a defined risk threshold through a human-in-the-loop approval gate — the same pattern proven in the MCP Human Approval Gateway lab — so autonomy stops at the boundary where a wrong action is expensive to reverse.
  • Tracked granted permissions against observed runtime behavior for every agent identity, so drift between what an agent was authorized to do and what it is actually doing becomes a monitored signal instead of a discovery made after an incident.

Outcome

A target-state model for agent identity that issues permission per task, re-evaluates it continuously, and treats human approval as a designed control rather than a fallback — replacing the standing-role, annual-review pattern that agentic workloads outgrow within days of deployment.
